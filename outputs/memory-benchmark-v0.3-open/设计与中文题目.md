# v0.3 开放建议：固定题目后比较 Medium 与 High

本版独立于旧24题及旅行扩展32题，旧数据和成绩均保留。模型回答为中文自然语言建议，不提供有限选项，不要求返回预设答案代号。题目与语义评分标准在真实运行前冻结。

## 本轮到底控制哪些变量

四个主要因素：上下文文字/事件长度、用户条件是否更新、时间信息是否提供、请求推理档位。实际经过时间另作为时间模块的测试因素（1分钟、1小时、1天），不是把所有因素做全面组合。

主模块8题：酒店和路线各自做短/长 × 保留/改变条件四格。同一题变体只更改一个条件事件。长版本比短版本多78条不改变核心条件的侧题事件；两种长度的当前时间和最新更新到当前的间隔相同。更新时间之后插入博物馆、咖啡、笔记本等主题，因此测试的是在更多无关上下文之后能否应用条件。

时间模块8题：天气4题（原发言时间未知、1分钟前、1小时前、1天前），相对日期4题（原日期已知/缺失两个对照）。两个缺失日期的提示相同，是配对对照的重复呈现，不是两个独立模板。不能把16题当成16个独立同分布样本。

每个模块使用同一题集先完整跑Medium，再完整跑High。模型请求标识为gpt-6-astra。未更改温度或输出长度设置，不做额外默认档位运行。

## 用户对“长对话”的最新澄清

用户真正关心的长对话尤其指现实时间跨度：一天说“今天健身、瑜伽、上课”，后来已到秋假且明确人在迈阿密。系统应让当日安排过期、新旅行位置生效，同时不推断永久退课、不再健身或所有长期偏好失效。

本轮主模块只测上下文内容变多，不是这个跨日组合；时间模块部分触及信息新旧，但没有完整覆盖上述组合。题目冻结后收到此澄清，所以不在正在运行的两档之间修改题目，也不把文本长称为“真实跨会话长期记忆测试”。后续版本应独立控制实际跨度和上下文大小，并分别评分临时安排、当前位置、长期偏好。

## 用户能看到的题目例子

| 模块 | 核心问题 | 合理响应 |
|---|---|---|
| 酒店，保留条件 | A便宜但已确认潮湿，B稍贵且干燥；预算内两家均无已报告虫害。用户保留不能潮湿的要求 | 明确推荐B并应用干燥要求 |
| 酒店，改变条件 | 唯一变化是用户明确接受潮湿，仍要最便宜的合格酒店 | 明确推荐A，不再强加旧偏好 |
| 路线，雨还在下 | 便宜A露天步行15分钟，B较贵全遮蔽；用户雨天不接受露天走，最新观察仍下雨 | 根据当前条件推荐B，不臆测人群危险 |
| 路线，雨已停止 | 唯一变化是最新观察说雨停且当前干燥 | 按成本偏好推荐A；不需要把两种天气都重新问一遍 |
| 天气原时间缺失 | 只知道以前说过“现在下雨”，不知道当时是哪天几点 | 承认无法算间隔，不编造当前天气，提出有针对性的当前确认 |
| 天气1分钟前 | 当前10点，雨况发言9:59，同一时区 | 算出1分钟，依据近期观察暂推荐遮蔽路线，不保证天气不会变 |
| 天气1小时前 | 当前10点，发言9点 | 算出1小时；确认当前天气，不能因过去一小时就断言雨停 |
| 天气1天前 | 当前次日10点，发言前日10点 | 算出24小时；同样不能推出雨停 |
| 原日期已知 | 原话“下周做研究”出于9月6日星期日或8月31日星期一；现在9月15日 | 周一至周日规则下，均指9月7–13日，已过去；不能据此说工作已完成 |
| 原日期未知 | 原话相同，但原发言日期缺失 | 无法定位原计划周，也无法判断该周是否已过；不能改为按今天算下周 |

天气时间题规定“5分钟以内观察可暂用于当前决策，更旧或无日期要先核验”，这是人为固定的诊断规则，**不是天气多久会变化的自然规律**。允许针对缺失信息提出一个确认，或明确说现状未知并保守选择遮蔽路线；只铺开所有如果分支、不给当前可执行下一步，不算通过。

## 如何评分

每题四个维度各0/1：结论是否合适、是否应用相关信息、是否避免编造确定性、是否避免不必要提问。原始题目没有标准答案泄露；评分时按rubric.json语义判断，不用某个固定词或标点作为唯一答案。主要通过率要求四项全通过；同时报告每个维度，避免把所有错误混成一个数。运行失败保留并计入分母。

近期雨况下带一句合理的变化提醒不算错误；但已有明确信息还反复要求用户重新提供，或对旧雨况直接宣称已停，属于不同错误。日期题必须算对目标周，但不同日期书写方式均接受。

评分由AI辅助检查，尚未经过独立人工评审；不是盲法专家标注。公开保存回答、分项判断与引用依据，供用户或研究者复核。不根据结果事后改标准，不保证一定出现失败，也不根据一题差异声称High更好。

## 重要边界

虽然包含用户/助手的多轮记录，本轮将完整记录一次性提供给每个新会话，是“对话回放输入”，并非真实逐轮生成、存储、检索和跨会话恢复。长版本将大量合成事件置于固定叙事时间内，是实验性长度干预，不能当作自然会话速度模型。所有酒店、价格、路线和天气事实均模拟，没有实际查询天气，没有复现原Gemini对话。

Codex自身会附加系统指令；不是纯API模型对比。独立会话无前题输出、无标准答案、禁止工具调用。记录请求档位和完整调用参数，服务端实际推理预算或底层快照若未暴露则明确未知。不能单靠“High”标签或消耗token多少证明更权威。

配置依据：[官方Codex配置参考](https://learn.chatgpt.com/docs/config-file/config-reference) 的 model_reasoning_effort 支持 medium 和 high；本次通过命令行显式传入。
